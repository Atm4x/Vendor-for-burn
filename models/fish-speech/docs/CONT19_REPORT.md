## Scope and provenance

Source baseline: CONT18 full source-only ZIP (`models/fish-speech`). Local development only, Rust 1.100.0, offline Cargo vendor from the previously acquired Git Bridge artifact. Original Python pipeline used as the behavioral specification. No model checkpoint, NVIDIA GPU, or TensorRT-RTX runtime was available for inference checks.

## Implemented in Rust

1. `src/trtx_engine.rs` — deterministic, validated names of TensorRT inputs and outputs; expected byte sizes and runtime device-region admission; real `trtx::Builder`-based serialized network construction; real `ExecutionContext::set_tensor_address` and `enqueue_v3` on the caller's stream. This code is compiled, but engine creation on the actual NVIDIA SDK remains untested.
2. `src/trtx_lowering.rs` — explicit output tensor naming, needed for runtime bindings rather than relying on unstable autogenerated TensorRT names.
3. `src/cuda_stream.rs` — optional `cuda-driver` backend using `cudarc 0.19.10`: CUDA context, single nonblocking stream, stable Arc-owned allocations, BF16 K/V cache allocation, checked pitched `cuMemcpy2DAsync_v2` (not a capacity-wide copy), synchronization, injectable network dispatcher.
4. `src/cuda_trtx.rs` — adapter mapping `TrtBlueprint` input and output bindings to device regions and submitting execution through the *same* stream, with explicit safety requirements for contexts and buffer lifetimes.
5. Cargo feature `cuda-driver` is optional and off by default; dependencies are pinned, Cargo.lock updated.

### Offline vendor blocker

The provided vendor's `cudarc-0.19.10/.cargo-checksum.json` expects SHA-256 `a53d4062...` for `src/cudnn/mod.rs` but the present file hashes to `775c724e...`. Cargo rejects the vendor before compiling even the driver-only feature (CUDNN itself is disabled). For the **specific GPU-feature compilation** only, the checksum metadata was temporarily normalized to match the local file and **restored immediately afterward**. Source code in the vendor was not edited. The default project tests are reproducible without this workaround. This must be fixed from a trusted offline vendor artifact before claiming clean reproducibility of the CUDA backend.
