# Stage 106 — NSF native polyphase/tiled CubeCL convolution, 2026-11-15

## Motivation / measured bottlenecks

From prior Stage 104/105 NCU raw export on RTX 4060, the original generic NSF upsample captured a 92.90 ms `direct_conv2d_kernel` with about 98.51% L1/TEX LSU throughput and 4.86% FMA pipeline utilization. NSF noise convolution captured a 59.53 ms `direct_conv2d_kernel` with roughly 54.61% L1/TEX LSU and 2.68% FMA pipeline. NCU instrumentation changes kernel duration: these numbers **are not** ordinary runtime latency or total NSF time. The engine-level ranking already established NSF as the main latency contributor, rather than RMVPE.

Generic `ConvTranspose1d` and `Conv1d` dispatch indirectly through N-dimensional Burn/CubeCL convolution, frequently involving Conv2d kernels, layout conversions and outer loops. Stage 105 register/spatial tiled RMVPE Conv2d did not address the dominant NSF operator shapes.

## New algorithms

### 1. Polyphase Temporal Pair transposed Conv1d

Files: `vendor/burn-cubecl-0.22.1/src/kernel/conv/conv_transpose2d/polyphase1d.rs`, `models/tts-with-rvc-rs/src/cubecl_conv.rs`, `models/tts-with-rvc-rs/src/decoder.rs`.

For output time `t` and padding `p`, choose `phase=(t+p) mod stride`. Only taps `k=phase + q*stride` contribute, and the original input index is `(t+p-phase)/stride - q`. The CubeCL kernel processes `t` and `t+stride` together, using the same weight vectors for both output accumulators, with channels in the innermost coalesced dimension. It supports grouped convolutions and unit dilation; unsupported dilation returns an error. The model caches the prepacked weight tensor `[Cin,K,Cout/group]` once. The original transposed convolution is preserved as fallback.

### 2. Single-input temporal-pair Conv1d for harmonic noise

Files: `vendor/burn-cubecl-0.22.1/src/kernel/conv/noise1d.rs` and same RVC adapter. Specialized shape `Cin=1,groups=1`, weight prepack `[1,K,Cout]`. Each filter weight vector updates two neighboring time positions, input scalars are broadcast into the output-channel vector, and the kernel stores `[N,T,Cout]` with NCT metadata view. No im2col/col2im, no intermediate zero-upsampled signal, no global atomics. Supports arbitrary positive stride/dilation and symmetric or asymmetric padding via `ConvOptions<1>`.

### 3. No universal Winograd substitution

3×3 Winograd on ordinary dense Conv2d is still a valid separate future backend, as cuDNN NCU confirmed. However transposed 1D with stride>1 and single-input noise Conv1d do not have the same filter structure. Applying F(2×2,3×3) to them is not a valid one-for-one replacement. The stage instead removes their fundamental wasted traffic and index work while retaining FP32 reduction semantics.

## Rollout safety

Existing kernels remain defaults. Set `RVC_NSF_POLYPHASE=1`, `RVC_NSF_NOISE_TILED=1` to enable the new paths, prepacking model weights at load. Run matched full-output parity, RTX NCU and 12-second WAV/PCM before changing defaults. Avoid activation for unsupported ConvTranspose dilation (only dilation 1 is currently wired into NSF).

## Stage 107 decision gates

Compare matched ConvTranspose and Noise Conv1d against their original Burn kernels using normal synchronized GPU timing (not NCU replay). Confirm `max_abs<=1e-4`, no NaN/Inf, and end-to-end WAV parity. Use NCU for actual SM compute utilization, L1TEX LSU wavefronts, eligible warps, registers/thread, spills and SASS FFMA. If original upsampling remains memory-limited, move to shared-memory/output-channel tiled scheduling using the now specialized polyphase mapping, avoiding a generic im2col. Evaluate register-tile sizes 2/4, coalesced weight layouts and per-stage dispatch before enabling in production.
