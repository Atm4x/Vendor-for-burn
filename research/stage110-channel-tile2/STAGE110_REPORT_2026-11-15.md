# Stage 110 — Output-channel tile2 for NSF polyphase ConvTranspose1d

Date: 2026-11-15. Repository `Atm4x/Vendor-for-burn`, PR #2, toolchain Rust 1.100.0, CubeCL via `burn-cubecl` 0.22.1.

## Measured Stage 109 findings (RTX 4060)

Source: user-provided `RVC_STAGE109_POLYPHASE_ILP_RESULTS.zip` (12 benchmark results and 12 NCU reports) and `exported_csv(4).zip` (12 CSVs, 2 profiled compute-kernel actions each). All 12 full-output parity checks reported PASS. The largest deviation was 1.90e-7. NCU timings are instrumented and cannot be directly compared to synchronous wrapper benchmark timings.

| Case | Single CUDA kernel | Pipe4 | ILP4 | ILP4 KIC |
|---|---:|---:|---:|---:|
| upsample8 | 48.75 us | 57.60 us | **44.91 us** | 44.91 us |
| upsample10 | 121.55 us | 153.58 us | 107.18 us | **103.50 us** |

ILP4 cut Long Scoreboard stalls from 12.77 to 5.80 for stride8, and 16.13 to 6.56 for stride10, with 62 registers/thread vs 40 for Single. FMA pipeline throughput increased from ~30% to ~34%. Pipe4 *increased* stalls (18.19, 22.72) despite preserving summation order. Host timing was mixed: for stride8 ILP4 was slower than Single (0.0708 vs 0.0632 ms); for stride10 ILP4 won (0.1002 vs 0.1117 ms). The gains are not universal, and no full NSF/PCM latency was measured.

The remaining resource cost is redundant input-channel loads: separate output-channel vectors independently fetch the same input sample. KIC changes weights' physical order but did not improve kernel latency. A new channel-tiled dataflow is more justified than another layout permutation.

## Stage 110 algorithm

New `polyphase_channel_tile2_kernel` computes two neighboring output-channel vectors for the same time and group per GPU lane, reusing each input scalar across both vectors. Tiling groups is explicit, so pairs cannot silently cross group boundaries. An odd last vector in a group is masked without losing output elements. The kernel supports existing prepacked `[Cin, K, Cout/groups]` weights and uses same output NCT metadata shape (no new input transpose, zero-fill or GEMM intermediate).

Two opt-in strategies in the Stage106 probe:

- `tile2`: two FP32 accumulators, one per output-channel vector, preserving the input-channel reduction order for each output;
- `tile2_split`: two independent even/odd accumulators per output vector (four total) to expose FMA ILP at the cost of some extra registers and reassociation.

Both are isolated probe modes. Production NSF selection and model weights are unchanged. The new kernel is not claimed to be faster until GPU measurements.
