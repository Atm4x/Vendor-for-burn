# Stage 90 — global RVC segmentation

The exact source algorithm and its unit tests are in `models/tts-with-rvc-rs/src/chunk_plan.rs` and `models/tts-with-rvc-rs/src/chunked.rs`. Production keeps `RVC_CHUNK_STRATEGY=fixed` unless explicitly overridden.

`RVC_CHUNK_STRATEGY=quiet-splice` selects a global minimum-energy partition into segments under the current 10-second model-input limit. `RVC_QUIET_EXTRA_CHUNKS=0..3` permits trading one or more extra model calls for substantially quieter cut boundaries. The plan is computed from high-pass-filtered 16-kHz PCM once before inference. Each output frame is generated by exactly one segment, with no overlapping core-window fade. Context is reflected independently around each segment. F0/Mel prepasses use the identical plan for slicing and alignment. This is **not** exact WAV parity with the old chunk geometry or Python 60-second segmentation.

Build and run offline tests using Rust 1.100:

```sh
rustc --edition=2024 --test research/stage90-global-chunks/chunk_test_harness.rs -o stage90_chunk_tests
./stage90_chunk_tests
```

For precise measurement of the *model input workload* on the original private WAV (no inference/GPU required):

```sh
rustc --edition=2024 -O research/stage90-global-chunks/measure_real.rs -o stage90_measure
./stage90_measure /path/to/MitaKind.wav
```

The actual WAV performance/quality gate is `research/stage37-windows-gpu-bench/windows/Run-RVC-Full-Stage90.ps1`. It requires the new Stage90 EXE and the user's existing `embed` directory. This Windows runner performs A/B/C/C/B/A tests and saves `RVC_STAGE90_FULL_WAV_RESULTS.zip`.
