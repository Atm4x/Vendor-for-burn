## Hardware kernel comparison

| FP32 dense 3×3 | Burn Direct | Burn 2×2 Reuse | cuDNN Winograd compute kernel |
|---|---:|---:|---:|
| B2, C32→32, 64×64 | 456.38 μs | 138.18 μs | 27.65 μs |
| B1, C64→64, 48×48 | 578.72 μs | 185.41 μs | 27.90 μs |
| Registers/thread | 48 | 118 | 130 |

Winograd computation's 27.65/27.90 μs excludes the separate `generateWinogradTilesKernel` launches and is not total PyTorch Conv2d latency. It does not establish use of Tensor Cores: the compact PyTorch export does not contain Tensor Core utilization.

### NCU wide-shape core metrics

| Metric | Direct | Reuse |
|---|---:|---:|
| Kernel runtime | 578.72 μs | 185.41 μs |
| L1TEX LSU wavefront throughput | 83.89% | 71.56% |
| SM compute throughput | 7.38% | 13.58% |
| Achieved active warp occupancy | 67.90% | 26.49% |
| Eligible warps per scheduler per active cycle | 0.13 | 0.23 |
| Registers/thread | 48 | 118 |
| Tensor pipe cycles (% of elapsed peak) | 0% | 0% |

This supports reducing live per-thread data. Although Reuse's occupancy is lower, eligible warps **rise**, so occupancy reduction alone cannot be taken as the dominant remaining bottleneck. L1TEX pressure remains high; DRAM bandwidth saturation is not established. NCU's `Estimated Speedup` is an advisory model, not an achieved gain.

## Stage 105 intervention: horizontal spatial pair

The 2×2 Reuse kernel has a 4×4 footprint (16 input vectors plus four output accumulators per input-channel tile) and 118 registers/thread. Stage 105 adds a *1×2 horizontal spatial pair* with a 3×4 footprint (12 input vectors plus two accumulators). The pair trades some cache reuse for fewer live values and more blocks:

| Static input-vector reads per 2×2 region, per input-channel vector | Count |
|---|---:|
| Direct | 36 |
| Reuse 2×2 | 16 |
| Pair 1×2 run twice | 24 |

These counts measure program loads in the ideal interior, **not** hardware L1 transactions or observed performance. Larger grid and smaller live vectors could improve scheduler utilization or lose to extra memory pressure. Need NCU measurement for register count, occupancy, L1TEX, instruction stalls and actual time.

Implementation: opt-in `conv_forward_spatial_pair`, enabled in RMVPE by `RVC_RMVPE_UNET_SPATIAL_PAIR=1`. It remains disabled by default. It only supports dense FP32 3×3, stride=1, dilation=1, padding=1, NCHW API with internal channels-last layout. The GPU probe uses `RVC_STAGE103_STRATEGY=pair`. Existing strategies are unchanged.
