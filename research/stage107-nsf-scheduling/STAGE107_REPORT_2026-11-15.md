The polyphase compute path issues fewer warps: upsample8 eligible warps per scheduler per cycle 0.984 → 0.565, issue-active 0.452 → 0.293, total CUDA grid blocks 256 → 128. Thus Stage 106's main ConvTranspose1d gain comes from removing conversions, not a faster core kernel. The new experiment prioritizes launch-level parallelism and register budget, rather than reducing global-memory transactions further at the cost of execution throughput. Do not equate NVIDIA counter replay times with synced overall CPU/operator medians.

## Implementation

### A. Polyphase Single (research-only)

Added `polyphase_single_kernel` and `conv_transpose1d_polyphase_single_packed` to Burn CubeCL. This keeps output-channel vectorization and prepacked `[Cin,K,Cout/groups]` weights but changes output ownership from **two same-phase samples/thread** to **one sample/thread**. On the Stage106 benchmark geometry, this doubles potential thread-level work items (and therefore grids, at fixed block size), reduces live accumulators from two to one, and splits interior taps from boundary handling. The tradeoff is additional redundant weight loads between neighboring times; benchmark determines whether more eligible warps outweigh lost reuse.

### B. Noise Interior (research-only)

Added `conv1d_single_input_packed_interior`, using a CubeCL compile-time branch of `noise_temporal_pair_kernel`. For fully interior temporal pairs, each tap performs two unconditional source loads and FMAs; boundary pairs retain the exact guarded Stage106 path. A separate `tiled` mode preserves the Stage106 implementation. Inference default is not switched.

Neither strategy creates zero-expanded intermediate tensors, `im2col`, or adds a CPU transfer. Packing is performed outside timed kernel loops. Both paths maintain FP32 summation ordering for each sample.

## Windows profile run

Download the workflow artifact `rvc-stage107-nsf-scheduling-windows-x64` from PR #2 and run in an Administrator PowerShell on RTX 4060:

```powershell
.\Run-RVC-Stage107-NSF-Scheduling.ps1 -Profiler ncu -Backend cuda -Runs 12 -NcuLaunchCount 3 -PythonExe "D:\Projects\tts-with-rvc\.venv\Scripts\python.exe"
```

For a fast timing-only parity check: `-Profiler none`. Default: 12 runs (Direct, Stage106, Stage107 for two upsampling and two noise configurations). The runner verifies NVTX DLL startup before any NCU commands. Output: `RVC_STAGE107_NSF_SCHEDULING_RESULTS.zip` without WAV/model content.

Interpretation criteria: Polyphase Single must beat Polyphase Pair in measured operator time and not materially worsen relative error, preferably also lowering compute-kernel time and improving eligible warps/SM occupancy. Noise Interior must improve tiled noise without becoming register/L1 bound. If a candidate loses, keep Stage106 and design a different output-channel/temporal tile.
